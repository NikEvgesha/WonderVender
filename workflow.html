Трое у котла.

Игра живёт в master и рабочих ветках. Доска и HTML-документы живут в отдельной ветке team-board того же репозитория.

Подключиться к доске

Нужны Git, Node.js 20+ и доступ к репозиторию GitHub по SSH. Каждый делает отдельную копию рядом с Unity-проектом. Настрой имя и адрес автора коммитов, если они ещё не заданы; для имени удобно взять свой уникальный логин GitHub. Имя используется как владелец карточки, поэтому договоритесь о едином написании и не меняйте его, пока держите задачи.

git clone --single-branch --branch team-board git@github.com:NikEvgesha/WonderVender.git WonderVender-Team
cd WonderVender-Team
git config user.name "ТВОЙ_ЛОГИН"
git config user.email "ТВОЙ_EMAIL_ДЛЯ_GIT"
node board.mjs

Открой 127.0.0.1:8765. Терминал остаётся открытым, пока нужна доска. Если порт занят, запусти node board.mjs serve --port 8766 и открой адрес из терминала. Для чтения документации можно просто открыть design.html в браузере.

Взять дело и договориться о сцене

  1. Выбери карточку «Готово взять». Уточни критерий и реальные пути Unity, за которые берёшься. Начальные пути на карточках — предлагаемые границы, папок может ещё не быть.
  2. Поставь «В работе» и дождись сохранения. Карточка покажет твой логин. «На ревью» сохраняет резерв, «Готово» или «Готово взять» освобождает зону.
  3. Пересечения проверяются по имени и вложенности путей. Например, Assets/Scenes пересечётся с Assets/Scenes/Shop.unity. Общую сцену, префаб или ProjectSettings указывай отдельно, если собираешься туда писать.
  4. Доска проверяет карточки, Git не блокирует Unity-файлы физически. Если задел чужой префаб, сначала договорись с владельцем; при необходимости вынесите правки в отдельный префаб или отдайте их одному интегратору.

Сохранение карточки создаёт коммит и отправляет его в team-board. У остальных открытая доска проверяет GitHub примерно каждые 15 секунд. Если два человека одновременно взяли одну карточку или пересекающиеся зоны, доска сохранит первую операцию, а второй покажет конфликт.

Тот же процесс для ассистента

Команды выполняются в копии доски с тем же Git-автором. Они используют те же правила резервирования и сразу отправляют успешное изменение в GitHub.

node board.mjs list
node board.mjs add --title "Звук разбитой склянки" --status ready --areas "Assets/Prototype/Audio"
node board.mjs set WV-001 --status doing

Карточка — отдельный JSON-файл в tasks/. Обновляй HTML и код доски отдельными коммитами в team-board, после обновления кода перезапусти сервер. Сохрани и отправь ручные изменения через Git перед синхронизацией доски: сервер не будет затирать рабочую копию с несохранёнными правками. Без связи показывается последняя локальная копия; запись подтверждается только после принятия GitHub. Если ответ от GitHub пропал после отправки, обнови доску и проверь, появилась ли карточка, прежде чем создавать дубликат.

Рабочие ветки игры

  1. В копии Unity-проекта проверь git status. Начинай работу с чистой копии: git switch master, git pull --ff-only, затем git switch -c feat/wv-001-grab.
  2. Коммить по смыслу вместе с Unity .meta. Не добавляй Library, Temp или Builds. Укажи номер карточки в сообщении или названии PR.
  3. Отправь ветку и открой PR в master. В описании — что стало возможно в игре, как это проверить и какие общие сцены тронуты. После проверки и слияния отметь карточку «Готово».

Стартовое разделение на троих: один ведёт захват и предметы, второй — котёл и зелья, третий — прилавок и тестовую сцену. Каждый работает в своём префабе. Владелец сцены собирает их после проверки. Это предложение по зонам, реальные владельцы появятся после назначения.
